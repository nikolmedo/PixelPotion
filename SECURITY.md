# Security Policy

## Reporting a vulnerability

Please report vulnerabilities privately, not in a public issue.

1. Open the repository's **Security** tab on GitHub.
2. Choose **Report a vulnerability** and describe the problem, the affected version and how
   to reproduce it.

If that button is not available, open a regular issue that only asks for a private contact,
without any details of the vulnerability.

## Supported versions

Only the latest release gets security fixes. Update with
`sudo bash /home/pi/pixelpotion/update.sh`. Installs from v2.0.2 or earlier need one
fresh run of `install.sh` first (see the README, "Updating").

## Security model

PixelPotion is a hobby device for a home network. Read this before you put it somewhere
else.

### What the design assumes

- The web portal (port 8080) is reachable only from your home WiFi or from the device's own
  setup hotspot.
- Everyone who can reach the portal is trusted. **There is no login.** Anyone on the network
  can take photos, view and delete queued photos, edit styles, change settings and trigger a
  WiFi scan.
- The portal is plain HTTP. **There is no TLS**, so traffic on the network, including keys
  typed into the settings form, is not encrypted by PixelPotion.

### What is protected

- **CSRF:** every POST needs a per-session token, so another website open in your browser
  cannot change the camera's settings or take photos.
- **Secrets are never rendered:** the WiFi password, Gemini key and Telegram token are not
  sent back to the browser after they are saved.
- **Secrets at rest:** `config.json` and `wpa_supplicant.conf` are mode 0600. The WiFi
  password goes to `sudo tee` on standard input, never on a command line or in a temporary
  file. The Telegram token is removed from logged errors.
- **Unprivileged service:** the app runs as `pi`, not root. Network changes go through
  `sudo -n` limited to exact command lines in `/etc/sudoers.d/pixelpotion`, validated with
  `visudo` on install and update.
- **Per-device hotspot password:** generated by `install.sh` and stored in
  `/etc/hostapd/hostapd.conf` (mode 0600).
- **Queue file names:** gallery routes accept only plain `.jpg` names inside the photo
  queue, so they cannot reach other files.

### Known limits

- **`/etc/dhcpcd.conf` write is root-equivalent in theory.** The service may write that file
  through `sudo tee`, and dhcpcd's `script` option can run a program as root. The whitelist
  narrows what a compromised service can do, but does not remove this path. Moving network
  management to NetworkManager is the planned fix.
- **No authentication and no TLS** on the portal, as described above.
- **Photos leave the device:** they are sent to Google Gemini and Telegram, and copies stay on
  the SD card until you delete them.
